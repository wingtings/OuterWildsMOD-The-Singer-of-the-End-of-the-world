# 5.30 Unity 端 MMD 模型技术美术（TA）优化操作指南

> 目标：把歌者（阿绫）这套 MMD 模型从现在的 Standard PBR（发灰发塑料）改造成卡通渲染，
> 用**开源、且与 OW 运行环境兼容**的渲染方案，在 Unity 2019.4.39f1 + 内置管线下落地，
> 并能正确打进 AssetBundle、随 New Horizons 加载进游戏。
>
> 本指南续接 [`5.28_TA.md`](5.28_TA.md)（那篇定了"为什么要在 Unity 端用卡通 shader、Blender 节点带不进来"的大方向），
> 这里只讲 **Unity 端的具体落地**：选型论证 → 原理 → 配库 → 逐材质操作 → 批量脚本 → FFT 自发光联动 → AssetBundle 打包 → 排错。

## 0. 先锁死三条硬约束（决定了"能用什么"）

这三条是从工程里直接核出来的，不是假设，所有选型都必须满足：

| 约束 | 实测来源 | 含义 |
|------|---------|------|
| **Unity 2019.4.39f1** | `outer-wilds-unity-template/ProjectSettings/ProjectVersion.txt` | 模板工程版本，必须与 OW 一致，**不能升** |
| **内置渲染管线（Built-in RP）** | OW 本体就是内置管线 | URP/HDRP 专用 shader **不能用**（进游戏直接粉红） |
| **Linear 色彩空间** | `ProjectSettings.asset` 里 `m_ActiveColorSpace: 1` | 卡通 shader 必须按 Linear 调色，和 OW 匹配（这点是好消息，省去 Gamma↔Linear 的偏色坑） |

还有两条来自加载链路的约束（见 `singer_world.json:165-168`）：

```jsonc
{
  "comment": "歌者·阿绫(MMD 模型,AssetBundle: assets/models/singer) —— 北极平台",
  "assetBundle": "assets/models/singer",   // ← 角色从这个 bundle 加载
  "path": "Assets/Model/Singer.prefab",     // ← bundle 里的 prefab
  "rename": "歌者(阿绫)"
}
```

- **角色不是走 `assets/shaders/shaders` 那个后处理 bundle**，而是单独的 `assets/models/singer` bundle，里面是 `Singer.prefab`。
- 所以：**卡通 shader 必须跟着 `Singer.prefab` 的材质一起被打进 `assets/models/singer` 这个 bundle**（材质引用 shader → 打包时 shader 被自动纳入），而不是后处理那条线。
- 源 FBX：`outer-wilds-unity-template/Assets/Model/世末歌者fbx.fbx`；材质在 `Assets/Materials/`（共 30+ 个）。

## 1. 选型：三个候选，为什么选 UTS2 为主、lilToon 为备

`5.28_TA.md` 提了 UTS2，也让我"调研更新更成熟的库或管线"。我把内置管线下能用的开源卡通方案全部核了一遍：

| 方案 | 开源/协议 | 内置管线 | 2019.4 支持 | AssetBundle 友好度 | 结论 |
|------|----------|---------|------------|-------------------|------|
| **UnityChanToonShader 2 (UTS2)** v2.0.9 | 是 / MIT-style（Unity-Chan 许可） | ✅ 原生 | ✅ Shader 兼容 5.6.7f1+，样例需 2019.4.31f1+ | ⭐ **高**：固定 shader 集、变体可控 | **主选** |
| **lilToon** 最新版 | 是 / MIT | ✅ 支持 | ✅ 2018.4+ | ⚠️ 中：über-shader、关键字变体多，"减体积"优化只在装了 VRCSDK 时触发 | **备选/进阶** |
| **Unity Toon Shader (UTS3, `com.unity.toonshader`)** | 是 / Unity Companion | ✅ 支持 | ❌ **最低 2020.3.45**，明确不再支持 2019.4 | — | **直接淘汰** |
| 现状 Standard PBR | — | — | — | — | 二次元模型的灾难（发灰发塑料） |

**结论与理由：**

1. **UTS3（Unity 官方"UTS2 继任者"）在我们这版 Unity 上根本装不了**——它最低要 2019.4 之后的 2020.3.45。5.28 里把它列为"successor"是对的，但版本对不上，**不要在它身上浪费时间**。

2. **UTS2 是内置管线 + 2019.4 的最佳匹配**：专为内置管线写、固定 shader 集（`DoubleShadeWithFeather` 等几个），变体数量可控，打进 AssetBundle 最稳。原生支持卡通三段色阶、Rim Light、MatCap（正好喂 MMD 的 SPH/SPA 球面贴图）、反向壳描边、Emissive——MMD 要的全有。**作为要交付进游戏的主方案。**

3. **lilToon 更现代、更"成熟"，但有 AssetBundle 风险**：它是 MMD/VRChat 社区现在的事实标准，功能比 UTS2 多（多层、距离渐变、更细的描边/MatCap、UV 动画），MIT 协议、维护活跃。**但**它是一个巨型 über-shader，靠大量 shader keyword 切功能；它那套"自动减体积"优化**只在导入了 VRChat SDK 时才触发**，我们打普通 AssetBundle 时不触发，可能导致变体爆炸 / 进游戏因关键字被剥离而粉红。**所以 lilToon 列为备选/进阶**：想要更顶的画面、且愿意处理变体问题时再上（见 §8.3）。

> 一句话路线：**先用 UTS2 把画面从"塑料"拉到"二次元"并确保能进游戏；UTS2 跑通、bundle 验证 OK 之后，若还想再提画质，再评估 lilToon。**

## 2. 卡通渲染原理（为什么这么调，调的是什么）

调 UTS2 前先建立心智模型，否则面板里几十个参数会一团乱。卡通渲染相对 PBR 的核心区别是：**把"连续的光照→颜色"映射换成"阶梯式的硬分界"**，再叠几层专门为二次元服务的补光。

### 2.1 色阶（Cel / Ramp）—— 卡通的命脉
- PBR：光照强度 `N·L` 连续地决定明暗，过渡平滑 → "真实但平淡"。
- 卡通：把 `N·L` 在某个阈值处**硬切**成"亮部色 / 一阶暗部 / 二阶暗部"几档。
- UTS2 用三张色 + 两个分界控制：
  - `Base Map / BaseColor`：亮部（受光面）。
  - `1st Shade Color`：一阶暗部（普通阴影）。
  - `2nd Shade Color`：二阶暗部（最暗、缝隙/背光）。
  - `BaseColor Step`、`ShadeColor Step`：分界**位置**（切在哪）。
  - `Feather`：分界**软硬**（0=硬切赛璐珞，>0=带点羽化）。
- **经验**：暗部色不要直接拿亮部调暗的灰色，要往**冷一点、偏紫/偏蓝**走（MMD 的 `toon.bmp` 暗部就是这么干的），这样阴影才"通透"不脏。

### 2.2 Rim Light（轮廓光 / 边缘光）
- 在视线与法线接近垂直的边缘加一圈亮光（基于 `1 - N·V`，即菲涅尔思路）。
- 作用：把角色从背景里"剥离"出来。**我们是阴雨 + 神光场景，逆光轮廓光会非常出彩**，强烈建议开。

### 2.3 MatCap（球面环境贴图）—— 直接接管 MMD 的 SPH/SPA
- MatCap = 一张"球面预渲染高光/反射图"，按法线朝向采样，廉价地伪造金属/水润/高光质感。
- **MMD 模型自带的 `.sph`（球面乘算）/ `.spa`（球面加算）就是 MatCap**。导入 Unity 后这些贴图还在，UTS2 有专门的 MatCap 槽：
  - `.sph`（乘算）→ MatCap 用 **Multiply/Blend** 模式。
  - `.spa`（加算）→ MatCap 用 **Add** 模式（UTS2 里 `_Is_BlendAddToMatCap = 1`）。
- 这样原模型作者给眼睛、金属件、头发高光设计的质感能原样保住。

### 2.4 Outline（描边）—— 反向壳法
- 原理：复制一遍网格 → 把它沿**法线方向**外推一点 → 翻面（只渲染背面）→ 涂纯色（通常暗色）。正面被原模型挡住，只在边缘露出一圈 = 描边。
- UTS2 内置，模式选 `Normal Direction`，宽度调小，颜色取比暗部更深的色。
- **前置条件**：法线必须干净（见 §4 的 FBX 导入设置——这就是 5.28 反复强调"法线是卡通命脉"的原因；法线乱 → 描边和色阶一起崩）。

### 2.5 Emissive（自发光）—— 接你的 FFT 系统
- 自发光不参与光照计算，直接加到最终色上 → 用于发光部件。
- 模型自带 `外套音频可视化 / 外套心跳 / 耳机波形 / 耳机音频可视化 / 耳机心跳` 这几个材质，就是原作者留的自发光位。
- §7 会把它们接到你已有的 `AudioVisualizerController`，**每帧按 FFT 频谱/心跳节拍改自发光颜色**——这是本项目最值钱的 TA 亮点（角色衣服随歌声律动）。

## 3. 环境配置：把 UTS2 装进模板工程

### 3.1 下载 UTS2 v2.0.9
- 官方仓库：<https://github.com/unity3d-jp/UnityChanToonShaderVer2_Project>（release/legacy/2.0 分支，v2.0.9）
- 也可从官网取 `.unitypackage`：<https://unity-chan.com/download/releaseNote.php?id=UTS2_0>
- 我们只要 shader 本体，**不要导整包**（样例场景/模型会拖慢工程、增加无关变体）。仓库里找 **`UTS2_ShaderOnly`** 那个精简包；若只有整包，导入后只保留 `Assets/Toon/` 下的 shader 与 `Editor`（材质 Inspector GUI），其余删掉。

### 3.2 导入
1. 打开模板工程 `outer-wilds-unity-template`（Unity 2019.4.39f1）。
2. `Assets ▸ Import Package ▸ Custom Package…` 选 UTS2 的 `.unitypackage`，或直接把仓库的 `Assets/Toon` 拖进 `Assets/`。
3. 导入后确认菜单/Shader 下拉里出现 `UnityChanToonShader/...`（如 `Toon_DoubleShadeWithFeather`）。

### 3.3 工程级设置（关键，决定进游戏不粉红）
- **色彩空间**：`Edit ▸ Project Settings ▸ Player ▸ Other Settings ▸ Color Space = Linear`。本工程已是 Linear（`m_ActiveColorSpace: 1`），核对即可。
- **Always Included Shaders（防变体被剥离）**：`Edit ▸ Project Settings ▸ Graphics ▸ Always Included Shaders`，把用到的 UTS2 shader（至少 `Toon_DoubleShadeWithFeather`，若用到描边/其他变体一并加）加进去。**这是 AssetBundle 进游戏不粉红的核心保险**。
- 建议建个目录放转好的材质，别和后处理材质混：沿用现有 `Assets/Materials/` 即可（角色材质本来就在这）。

## 4. 模型导入设置复核（卡通成立的前提）

详细的 Blender 清理在 [`5.28_TA.md` §3](5.28_TA.md) 已写，这里只复核 **Unity 端 FBX 导入设置**——这几个开关错了，后面再怎么调 UTS2 都白费。选中 `Assets/Model/世末歌者fbx.fbx`，Inspector：

- **Model 页**
  - `Scale Factor`：核对角色高度 ≈1.6–1.8m（MMD 单位 ≈0.08，常需放大）。
  - **`Normals = Import`**（不是 Calculate！）——保留 Blender 调好的自定义法线，**别让 Unity 重算把卡通法线和描边毁了**。
  - `Blend Shapes` 勾选（保住口型/表情 morph，少数能进 Unity 的"动画资产"）。
- **Rig 页**：用 Mecanim 人形动画就 `Humanoid`，否则 `Generic`。
- **Materials 页**：`Extract Materials` + `Extract Textures` 到工程，得到 `Assets/Materials/` 下那 30+ 个 `.mat`，再逐个/批量换 shader。

> 注意：`mmd_tools_rigid_*` 这几个材质是 MMD 刚体/物理占位，不是可见网格的外观材质，**换 shader 时直接跳过**它们。

## 5. 逐材质映射方案（针对本模型的 30+ 个材质）

工程里的角色材质可归成几类，每类的 UTS2 调法不同。下表是**具体到本模型材质名**的对照（材质名见 `Assets/Materials/`）：

| 类别 | 材质（本工程实名） | UTS2 设置要点 |
|------|-------------------|--------------|
| **皮肤** | `Body`、`nails` | 暗部往暖橙偏一点；Feather 稍大（皮肤过渡软）；Rim 弱；描边细 |
| **脸** | `_Face`、`FaceBrow`、`FaceEyeline`、`FaceMouth`、`Face_頬染め` | 脸尽量**少阴影**（二次元脸忌脏）：BaseColor Step 调高让大部分是亮部；眉/眼线/嘴这些线条材质**关描边**（本身就是线），勿叠 |
| **眼睛** | `EyeIris*`、`EyeWhite*`、`EyeHighlight` | `EyeHighlight`（高光）建议**走 Emissive 或 Unlit**，保住眼神光不被阴影吃掉；虹膜可挂 MatCap 做水润感 |
| **头发** | `_Hair_01`、`Hair_03`、`Hair_X`、`HairBack` | 头发是 MatCap 的主战场：把原 `.sph/.spa` 喂 MatCap 槽，恢复发丝高光；两段暗部拉开 |
| **衣物（裙/外套/围巾/手套）** | `内裙上/下/袖`、`外套灰/黑/扣`、`围巾`、`手套灰/红` | 标准三段色阶 + Rim + 描边；阴雨场景把整体暗部压沉一点 |
| **耳机外壳** | `耳机X/后/红/黑` | 硬表面：Feather 调小（硬分界）、可上 MatCap 做塑料/金属反光 |
| **★ 自发光（接 FFT）** | `外套音频可视化`、`外套心跳`、`耳机波形`、`耳机音频可视化`、`耳机心跳` | **开 Emissive**，初始 `_Emissive_Color` 给基色；运行时由 §7 的脚本每帧改色 |
| **跳过** | `mmd_tools_rigid_*` | 物理占位，不处理 |

**逐材质手动操作（以 `Body` 为例）：**
1. 选 `Body.mat`，Inspector 顶部 `Shader` 下拉 → `UnityChanToonShader/Toon_DoubleShadeWithFeather`。
2. `BaseMap` 拖入原皮肤贴图（换 shader 后 Unity 通常会保留 `_MainTex`，但要核对；UTS2 主贴图槽即 BaseColor 的 Base Map）。
3. `1st Shade Color` / `2nd Shade Color`：吸取贴图主色 → 压暗 + 往冷里挪一点，两档拉开。
4. `BaseColor Step ≈ 0.5`、`Feather ≈ 0.0001–0.05`（皮肤可大一点）。
5. `RimLight` 开，颜色淡、`Power` 中等。
6. 有 `.sph/.spa` 的材质：`MatCap` 开，贴图喂进去，加算图设 Add 模式。
7. `Outline`：`Normal Direction`，`Width` 小，`Color` 深。
8. F5 / 在 Scene 里看效果，微调 Step/Feather。

> UTS2 参数面板项很多，精确的属性显示名以 Inspector 为准；上面给的是功能位置。

## 6. 批量转换脚本（30+ 材质别手动点）

手动逐个换太累且易错。下面这个 Editor 脚本：**批量把选中材质从 Standard 转成 UTS2，迁移主贴图，按材质名分类设默认色阶/描边/自发光**，转完再逐个微调即可。

放到 `outer-wilds-unity-template/Assets/Editor/MmdToUTS2.cs`：

```csharp
using UnityEngine;
using UnityEditor;

// 批量把选中的材质转成 UTS2，并按材质名做分类预设。
// 用法：Project 窗口选中 Assets/Materials 下的角色材质 → 菜单 Singer ▸ Convert Selected → UTS2
public static class MmdToUTS2
{
    const string ShaderName = "UnityChanToonShader/Toon_DoubleShadeWithFeather";

    [MenuItem("Singer/Convert Selected → UTS2")]
    static void Convert()
    {
        var shader = Shader.Find(ShaderName);
        if (shader == null)
        {
            Debug.LogError($"找不到 {ShaderName}，先导入 UTS2。");
            return;
        }

        int n = 0;
        foreach (var obj in Selection.objects)
        {
            var mat = obj as Material;
            if (mat == null) continue;
            if (mat.name.StartsWith("mmd_tools_rigid")) continue; // 物理占位跳过

            // 1) 先抢救原主贴图（换 shader 前 Standard 的 _MainTex 还在）
            Texture mainTex = mat.HasProperty("_MainTex") ? mat.GetTexture("_MainTex") : null;
            Texture emiTex  = mat.HasProperty("_EmissionMap") ? mat.GetTexture("_EmissionMap") : null;

            // 2) 换 shader
            mat.shader = shader;

            // 3) 主贴图 → UTS2 的 BaseMap(_MainTex) 与一二阶 ShadeMap
            if (mainTex != null)
            {
                SetTex(mat, "_MainTex", mainTex);
                SetTex(mat, "_1st_ShadeMap", mainTex);
                SetTex(mat, "_2nd_ShadeMap", mainTex);
            }

            // 4) 通用卡通预设
            SetColor(mat, "_BaseColor", Color.white);
            SetColor(mat, "_1st_ShadeColor", new Color(0.78f, 0.74f, 0.82f)); // 偏冷一阶暗部
            SetColor(mat, "_2nd_ShadeColor", new Color(0.55f, 0.52f, 0.66f)); // 更冷二阶暗部
            SetFloat(mat, "_BaseColor_Step", 0.5f);
            SetFloat(mat, "_ShadeColor_Step", 0.35f);
            SetFloat(mat, "_1st2nd_Shades_Feather", 0.0001f);
            SetFloat(mat, "_BaseShade_Feather", 0.0001f);

            // 5) Rim Light 默认开
            SetFloat(mat, "_RimLight", 1f);
            SetColor(mat, "_RimLightColor", new Color(0.9f, 0.95f, 1f));

            // 6) 描边默认开（线条材质会在下面按名关掉）
            SetFloat(mat, "_Outline_Width", 0.6f);
            SetColor(mat, "_Outline_Color", new Color(0.18f, 0.16f, 0.22f));

            // 7) 按名分类微调
            string m = mat.name;
            if (m.Contains("Face") || m.Contains("Brow") || m.Contains("Eyeline") || m.Contains("Mouth"))
            {
                SetFloat(mat, "_BaseColor_Step", 0.75f);   // 脸少阴影
                SetFloat(mat, "_Outline_Width", 0f);        // 线条材质关描边
            }
            if (m.Contains("EyeHighlight"))
            {
                EnableEmissive(mat, emiTex, Color.white);   // 眼神光保亮
            }
            // ★ 自发光部件（接 FFT）
            if (m.Contains("音频可视化") || m.Contains("波形") || m.Contains("心跳"))
            {
                EnableEmissive(mat, emiTex, new Color(0.2f, 0.8f, 1f)); // 初始青蓝，运行时由脚本改
                SetFloat(mat, "_Outline_Width", 0f);
            }

            EditorUtility.SetDirty(mat);
            n++;
        }
        AssetDatabase.SaveAssets();
        Debug.Log($"[UTS2] 转换完成：{n} 个材质。请逐个进 Inspector 微调色阶。");
    }

    static void EnableEmissive(Material mat, Texture emiTex, Color c)
    {
        // UTS2 的自发光：属性名以你导入的版本为准，常见为 _Emissive_Tex/_Emissive_Color + 关键字 _EMISSIVE_SIMPLE
        if (emiTex != null) SetTex(mat, "_Emissive_Tex", emiTex);
        SetColor(mat, "_Emissive_Color", c);
        mat.EnableKeyword("_EMISSIVE_SIMPLE");
    }

    static void SetTex(Material m, string p, Texture t)   { if (m.HasProperty(p)) m.SetTexture(p, t); }
    static void SetColor(Material m, string p, Color c)   { if (m.HasProperty(p)) m.SetColor(p, c); }
    static void SetFloat(Material m, string p, float f)   { if (m.HasProperty(p)) m.SetFloat(p, f); }
}
```

**用法**：Project 里选中 `Assets/Materials/` 下所有角色材质（可多选）→ 菜单 `Singer ▸ Convert Selected → UTS2` → 再逐个进 Inspector 做艺术微调。

> ⚠️ UTS2 不同小版本的内部属性名可能略有差异（`_1st_ShadeColor` 等基本稳定，自发光相关偶有差异）。脚本里所有 `Set*` 都做了 `HasProperty` 判空，**属性名对不上只是不生效、不会报错**；先转一个材质，在 Inspector 里对照实际属性名，再批量。

## 7. ★ 自发光接 FFT —— 本项目的 TA 亮点

你已有的 `AudioVisualizerController`（`TheSingerOfTheEnd/.../AudioVisualizerController.cs`）每帧做：
```csharp
AudioListener.GetSpectrumData(_samples, 0, FFTWindow.BlackmanHarris);
// → 归一成 _bins[32]
_mat.SetFloatArray("_Spectrum", _bins);   // 喂给声波环 shader
```
现在把同一份频谱**复用**到角色的自发光材质上：低频段（贝斯/底鼓）驱动"心跳"材质，整体能量驱动"音频可视化"材质。这样歌者的衣服/耳机会随歌声呼吸发光，和声波环、神光串成一台演出。

新建控制器 `TheSingerOfTheEnd/TheSingerOfTheEnd/EmissivePulseController.cs`（思路示例，按你工程的命名与查找方式接入）：

```csharp
using UnityEngine;

namespace TheSingerOfTheEnd
{
    // 把实时 FFT 能量映射到歌者自发光材质的 _Emissive_Color。
    // 复用 AudioListener.GetSpectrumData（与 AudioVisualizerController 同源），
    // 不直接依赖歌者 AudioSource：玩家"听到多大声"，衣服就"发多亮"。
    public class EmissivePulseController : MonoBehaviour
    {
        private const int FftSize = 256;
        private readonly float[] _samples = new float[FftSize];

        private static readonly int EmissiveColor = Shader.PropertyToID("_Emissive_Color");

        // 运行时从歌者模型里按材质名抓到的实例材质
        private Material[] _beatMats;   // 心跳：跟低频
        private Material[] _waveMats;   // 音频可视化/波形：跟整体能量

        private Color _beatBase = new Color(1f, 0.2f, 0.35f);  // 心跳基色（红）
        private Color _waveBase = new Color(0.2f, 0.8f, 1f);   // 波形基色（青蓝）

        // 在 SetupGraphics 里、歌者就绪后调用，传入歌者根 Transform
        public void Bind(Transform singerRoot)
        {
            var rends = singerRoot.GetComponentsInChildren<Renderer>(true);
            var beat = new System.Collections.Generic.List<Material>();
            var wave = new System.Collections.Generic.List<Material>();
            foreach (var r in rends)
                foreach (var m in r.materials)   // .materials = 实例，避免改到共享材质
                {
                    if (m.name.Contains("心跳")) beat.Add(m);
                    else if (m.name.Contains("音频可视化") || m.name.Contains("波形")) wave.Add(m);
                }
            _beatMats = beat.ToArray();
            _waveMats = wave.ToArray();
        }

        private void Update()
        {
            if (_beatMats == null) return;
            AudioListener.GetSpectrumData(_samples, 0, FFTWindow.BlackmanHarris);

            // 低频能量（前 8 个 bin ≈ 鼓点/贝斯）
            float bass = 0f;
            for (int i = 0; i < 8; i++) bass += _samples[i];
            bass = Mathf.Clamp01(Mathf.Sqrt(bass) * 12f);

            // 整体能量
            float total = 0f;
            for (int i = 0; i < FftSize; i++) total += _samples[i];
            total = Mathf.Clamp01(Mathf.Sqrt(total) * 6f);

            SetEmission(_beatMats, _beatBase, bass);
            SetEmission(_waveMats, _waveBase, total);
        }

        private void SetEmission(Material[] mats, Color baseCol, float intensity)
        {
            // HDR 自发光：亮度随能量起伏，配合 §9 的 Bloom 会"晕开"
            Color c = baseCol * Mathf.LinearToGammaSpace(intensity * 3f);
            foreach (var m in mats)
                if (m.HasProperty(EmissiveColor)) m.SetColor(EmissiveColor, c);
        }
    }
}
```

接入点：在 `TheSingerOfTheEnd.cs` 的 `SetupGraphics()` 里、歌者就绪后（参考 `AudioVisualizerController` 里用 `FindDeep(planet.transform, "歌者(阿绫)")` 找歌者的写法）`AddComponent<EmissivePulseController>()` 并 `Bind(歌者Transform)`。

> 注意自发光属性名要和 §6 实际用的一致（这里用 `_Emissive_Color`）。要让发光"晕"出来，需要 §9 的 Bloom；没有 Bloom 时自发光只是变亮不发散。

## 8. 打进 AssetBundle 进游戏（OW MOD 必看，最容易踩坑的一段）

角色走的是 `assets/models/singer` bundle（不是后处理那个）。流程：

### 8.1 给 prefab/材质设 bundle 名
1. 在 Unity 里选中 `Assets/Model/Singer.prefab`，Inspector 最下方 `AssetBundle` 下拉设为 **`assets/models/singer`**（与 `singer_world.json:166` 一致，全小写）。
2. UTS2 材质被 `Singer.prefab` 引用 → 打包时 **UTS2 shader 会被自动拉进同一个 bundle**，无需手动给 shader 设 bundle 名。

### 8.2 防变体剥离（粉红的头号成因）
- §3.3 已把 UTS2 shader 加入 `Graphics ▸ Always Included Shaders`——**务必在执行打包的这个工程里设好**。
- 必须**在装了 UTS2 的工程里**执行打包：本工程已有打包脚本 `Assets/Editor/BuildBundles.cs`：
  ```csharp
  [MenuItem("Singer/Build AssetBundles")]
  // 输出到工程外 AssetBundles/，BuildTarget = StandaloneWindows64
  BuildPipeline.BuildAssetBundles("AssetBundles", BuildAssetBundleOptions.None, BuildTarget.StandaloneWindows64);
  ```
  菜单 `Singer ▸ Build AssetBundles` → 产物在工程旁的 `AssetBundles/` 目录。

### 8.3 拷贝到 MOD
- 把 `AssetBundles/assets/models/singer`（及其 `.manifest`）拷到 MOD 目录对应位置，使 NH 能按 `assets/models/singer` 找到（与现有 `assets/shaders/shaders` 同级的放法）。
- 角色材质走 prefab，不需要改 `AssetLoader.cs`（那只管后处理的 7 个材质）。

### 8.4 进游戏验证（F7/F8）
- **粉红** = shader 没进 bundle / 变体被剥离 → 回 §3.3 加 Always Included、重打。
- **纯黑 / 过亮 / 偏色** = 色彩空间问题 → 确认工程是 Linear（OW 也是 Linear，应匹配）。
- **描边/法线乱** = FBX 导入 `Normals` 没设 `Import`（§4）。

> **lilToon 走这条线的额外坑**（若选 lilToon）：lilToon 是 über-shader，关键字变体多，"减体积"优化只在装了 VRCSDK 时才触发。打 AssetBundle 时：① 务必把用到的 lilToon shader 全加进 Always Included Shaders；② 考虑用 lilToon 的"锁定材质（lock/optimize material）"功能先固化每个材质的变体，减少进游戏丢变体粉红的概率；③ 控制启用的功能数量。**这也是本指南把 lilToon 列为备选而非主选的根本原因。**

## 9. 配套后处理（让卡通+自发光真正"发光"）—— 衔接 5.28 §5

UTS2 卡通色 + 自发光部件 + 神光，需要 **Bloom** 才能成立（否则自发光只是"变亮"，不"发散"）。沿用 5.28 的路线 A：再写一个 `OnRenderImage` 的 Bloom（亮度阈值提取 → 高斯模糊 → 叠加）+ Color Grading，挂在 PlayerCamera 上，排在现有 GodRay/Fog 之后。挂载顺序（5.28 §5 已定）：
```
体积雾 → God Rays → Bloom → Color Grading → Vignette
```
这部分属于后处理工作流，本指南聚焦角色卡通本身，细节见 `5.28_TA.md` §5。

## 10. 落地顺序（建议）

1. **导入 UTS2 + 工程设置（§3）**——装库、Linear、Always Included Shaders。
2. **复核 FBX 导入设置（§4）**——`Normals=Import`、BlendShapes、Scale。
3. **跑批量脚本（§6）**——30+ 材质一键转 UTS2。
4. **逐材质微调（§5）**——脸少阴影、头发 MatCap、衣物三段色阶、描边。
5. **打 bundle 验证进游戏（§8）**——先确认"不粉红、卡通成立"，这是交付底线。
6. **接 FFT 自发光（§7）**——TA 亮点，角色随歌声律动。
7. **加 Bloom（§9）**——让自发光/神光发散成立。
8. 行有余力再评估 **lilToon（§1/§8.3）** 提画质。

## 11. 排错速查表

| 现象 | 最可能原因 | 处理 |
|------|-----------|------|
| 进游戏角色粉红 | shader 没进 bundle / 变体剥离 | Always Included Shaders + 在装了 UTS2 的工程重打 bundle（§3.3/§8.2） |
| 描边像爆刺 / 色阶破碎 | FBX 法线被 Unity 重算 | `Normals = Import`，必要时回 Blender 加 Weighted Normal（§4 / 5.28 §3） |
| 脸很脏、阴影一坨 | 脸用了标准三段色阶 | 脸 `BaseColor_Step` 调高、线条材质关描边（§5/§6） |
| 头发/眼睛塑料无高光 | 没接 MMD 的 sph/spa | 开 MatCap 喂球面贴图，加算图用 Add（§2.3/§5） |
| 自发光不"发散"只变亮 | 没有 Bloom | 加后处理 Bloom（§9） |
| 自发光不随音乐动 | 没 Bind 到歌者材质 / 属性名不符 | 核对 `EmissivePulseController.Bind` 与 `_Emissive_Color` 属性名（§7） |
| 整体偏色/过暗 | 色彩空间不符 | 工程设 Linear（§3.3） |
| lilToon 进游戏粉红 | über-shader 变体被剥 | 锁定材质 + Always Included（§8.3）；或退回 UTS2 |
